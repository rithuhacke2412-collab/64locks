64 Locks

Deterministic, fully offline password generator. One key file, one passphrase, one site name. No accounts, no sync, no vault.

Read me and terms

Read me

  • What it does. It makes a different long password for every site, URL or app from three things: your key file, your passphrase and the exact name you type. The same three things always give the same password, on any device. Nothing is stored or sent anywhere.
  • What you must keep. The key file (two backups in two places), the passphrase (in your head) and the exact way you write each site name.
  • What it cannot do. It cannot recover a lost key file or a forgotten passphrase, and it does not change your passwords on websites for you. You paste the result into the site’s password box yourself. It is not a vault.
  • Before you rely on it. Open Tips: important at the bottom of the page and read the do and don’t lists.

2 · Passphrase

The meter assumes a phrase you invented unless you tick the box, because it cannot tell random from chosen. Six random Diceware words (about 78 bits) is the recommended minimum.

3 · Site, URL or app

Every character counts. The name is used exactly as you type it. Capital letters, www., https://, a slash at the end, dots, dashes and spaces inside the name all change the password. Only spaces at the very start or end are ignored.

  • Do not remove www.. www.example.com and example.com give two different passwords.
  • Choose one way to write each site and always write it that way, for example always www.example.com in lower case.
  • Write down exactly what you typed, next to the account name, and keep that note away from your key file and passphrase.
  • For an app, type the name exactly as you decided, such as Instagram.
  • Need a new password for the same site? Raise the version below instead of changing the name.
  • If a password does not work, you probably typed the name differently. Try it with and without www. and with other capital letters.

The version number is mixed into the salt, so raising it gives a completely different password for the same site. That is how you rotate a password. The page remembers the highest version you copied for each site and key file (stored under a keyed hash, never the site name) and warns you if you go lower. It is only a warning: you can still use any version.

Tips: important

Do

  • Use a long passphrase. Six random words from dice or a generator is the target. Tick the “generated randomly” box only if that is really true.
  • Keep the two parts apart. Key file on a USB drive or other offline media, passphrase in your head. One alone is not enough to make your passwords.
  • Make two backups of the key file in two different safe places. If every copy is lost, every password made from it is lost, and nothing can recover it.
  • Write each site name exactly the same way every time. Capitals, www. and dots all matter. Keep a note of how you wrote each one, away from your key and passphrase.
  • Check the fingerprint shown when you load or type a key and compare it with your backup. It catches a mistyped key.
  • Raise the version to change a password (a site forces a change, or you think one leaked). The page warns you if you go lower.
  • Use hex32 or web mode when a site rejects long passwords or wants letters and digits.
  • Lock when you finish and close the tab, especially on a computer you do not fully control.
  • Use a trusted, updated device and a private window, with no browser extensions you do not trust.
  • Keep your own saved copy of this page and check that it says the startup check passed. Run ?selftest=1 after moving to a new device.
  • Keep each account’s own recovery codes somewhere safe, separate from this tool.

Don’t

  • Don’t store the key file and the passphrase together, and never in email, cloud notes, chat or photos.
  • Don’t share the key file, the passphrase or the passwords, and don’t screenshot them.
  • Don’t use a famous phrase, song line, name, birthday or anything you use elsewhere as the passphrase.
  • Don’t type the passphrase anywhere except this page. Websites only ever need the finished password.
  • Don’t change how you write a site name (adding or removing www., https:// or a slash) unless you want a different password.
  • Don’t reuse an old version number for a new password.
  • Don’t use it on public or shared computers, or on a device that may have malware or a keylogger. No tool can protect you there.
  • Don’t get this page from a link or file someone sent you. A tampered copy could steal your passphrase. Use your own saved copy.
  • Don’t rely on the clipboard clearing. History tools may keep a copy. Paste, then lock.
  • Don’t edit the page’s code unless you know what you are doing. It is sealed with a security policy and will stop working.
  • Don’t make it your only protection for critical accounts such as banking until an independent security expert has reviewed it.

If something goes wrong

  • Key file lost: nothing can recover it. Make a new key and reset each account’s password through that site’s own recovery.
  • Key file stolen: they still need your passphrase, but treat it as serious. Make a new key and change your important passwords first.
  • Passphrase seen by someone: they still need the key file. Choose a new passphrase and change your passwords when you can.
  • A password does not match: check the site spelling, the version, the output mode and the fingerprint first.
Technical details

The passphrase is normalized (Unicode NFKD, trimmed, whitespace runs collapsed, case preserved). The site name is normalized only by Unicode NFC and trimming. A 32-byte salt is HMAC-SHA-256(K, "64locks/v2/salt|" + site + "|" + version) and a 32-byte input key is HMAC-SHA-256(K, "64locks/v2/pass|" + passphrase), where K is the 32-byte key. The final key material is Argon2id(ikm, salt, m=65536 KiB, t=3, p=1, 32 bytes, version 0x13). The hex64 password is that tag in hex and hex32 is its first 16 bytes. Web mode derives a second tag with the salt suffix |web, expands it with HMAC-SHA-256(tag, "64locks/v2/webstream|" + counter) and draws every character by rejection sampling: one lowercase letter, one uppercase letter, one digit and 17 from all 62, then an unbiased shuffle. The fingerprint is the first 8 hex characters of SHA-256("64locks/v2/fp|" + hex64).

At every start the page checks its Argon2d, Argon2i, Argon2id and BLAKE2b code against the official RFC 9106 test vectors and refuses to generate if one fails. New key files carry a 16-character id from a domain-separated SHA-256 of the key; older 8-character ids still load. Working buffers are zeroed after each derivation and the key is zeroed when you lock, but JavaScript strings (the passphrase and the password text) cannot be wiped and stay until the browser frees them. This page makes no network requests.

Self-test (?selftest=1)

Official vectors, golden vectors, offline audit, estimator, determinism and failure paths. The test never touches a key you have loaded: your key, fields and output are saved first and restored afterwards, and the form is locked while it runs. It needs about a minute.

Argon2id: pure-JavaScript port of the PHC winner reference implementation. Test vectors: RFC 9106. Everything runs locally in your browser, so pulling the network cable changes nothing.
